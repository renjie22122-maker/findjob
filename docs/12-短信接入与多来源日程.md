# 短信接入与多来源日程

## 使用入口

邮件分析页新增「短信接入」，粘贴正文后直接分析；收件时间可选，未知时仅以导入时间留档，不将它推断为投递日期。短信使用独立 `sms:` 内容指纹和「短信」主题／发送方标识，保存在同一通知收件箱。转发重试不会重复建档。配置了模型时使用现有模型，失败降级本地规则；证据不足或岗位不唯一时进入待处理。

短信无需邮件回执也能建考试；已有邮件则共用公司、职位编号、岗位、活动编号、时间及来源匹配规则。不同分公司／不同职位不会仅凭集团名称合并。短信链接、邮箱、密码及身份证号码先脱敏，不加载网页或考试客户端。

可以在手机端全量转发，让 FindJob 筛选。验证码／登录验证及明显无关内容在存储和模型调用之前过滤，返回成功的 `filtered` 状态避免手机反复重试；可能相关的通知会交给配置的模型判断。因此招聘关键词筛选不是完美的语义分类，手机端排除私人类别仍可进一步减少传输。不要开启通知监听或通话转发来替代短信权限。

## Android 安装和连接

使用 [SmsForwarder 官方发布页](https://github.com/pppscn/SmsForwarder/releases) 安装合适的 APK；不确定 CPU 架构时选 universal。按照 Android 提示授予接收／读取短信权限，为后台接收设置允许自启动及不受电池优化限制。只启用短信来源，不需要通讯录、定位、无障碍或全应用通知权限。不同厂商后台管理设置不同，安装后用测试短信验证。

FindJob 默认 3001 主端口没有远程鉴权，**不要把主端口暴露到手机网络或公网**。手机使用独立接收端口，只存在 `/ingest`，不能读取邮箱设置、数据库或应用列表。

在启动 FindJob 的进程中设置以下环境变量，然后启动 `node server/dist/index.js`：

```text
SMS_GATEWAY_PORT=3002
SMS_GATEWAY_HOST=127.0.0.1
SMS_GATEWAY_TOKEN=<至少32字符的随机令牌>
```

默认关闭网关，端口与令牌同时有效才启用。令牌建议使用密码管理器生成；不得提交仓库。`127.0.0.1` 只用于本机测试。手机远程使用时，选择专用的加密 VPN 网卡地址或只代理此端口的 HTTPS 服务；按该地址调整 `SMS_GATEWAY_HOST`。不要为短信接入改动主应用 `HOST`。HTTP 接收器本身不提供 TLS，Bearer 令牌必须经可信的加密传输；不要使用公共 Wi-Fi 明文转发所有短信。防火墙也只允许选定的手机／VPN 网络访问短信端口。

SmsForwarder 新建 Webhook 通道：

- URL：`https://你的短信专用入口/ingest`（或加密 VPN 内的 `http://VPN地址:3002/ingest`）。
- 方法：POST。
- 自定义请求头：`Authorization: Bearer <令牌>`。
- 消息模板使用原短信正文，`webParams` 留空；官方默认表单字段 `from`、`content` 已兼容。表单方式可正确编码引号和换行。
- 规则：仅短信，可全量转发，由 FindJob 做第一层筛选。启用失败重试；无关短信返回 200，不触发重试。

其他转发工具可使用 JSON：`{"sender":"发送方","body":"正文","receivedAt":"2026-10-22T10:00:00+08:00"}`，其中收件时间可省略。最多 12,000 字符，网关请求体限制 24 KB，每分钟最多 10 次请求；429 或 409 可稍后重试。默认表单的 `timestamp` 是转发时间，不擅自当作短信收到时间。

官方协议依据：[Webhook 说明](https://github.com/pppscn/SmsForwarder/wiki/附录1：向webhook发送post-get-put-patch请求)。手机安装、权限和可达的加密网络需要在设备上完成；本机测试通过不等于手机已连接成功。

## 日程关联、预通知与冲突

同公司、同发件邮箱、同活动类型与相同时间，且考试时间引文相同的准考证／考点补充通知，可唯一关联原场次；位置、轮次或岗位冲突仍阻止自动关联。保留提醒 ID 和已完成状态。

预通知里的笔试与面试分别跟踪。已明确的笔试时间正常提醒；只有日期范围的面试作为 `awaiting_time` 日程保留日期、参加条件及来源，不虚构 00:00 作为面试时刻。同一申请下的正式面试时间落在唯一预通知日期范围内时补齐原场次。参加过现场初面可免 AI 初面等条件会直接显示。

日程页提供「与同场日程共用提醒」。需要用户明确确认同一场活动，且类型、状态及起止时间一致；申请与来源不合并，准备事项仍独立，已完成记录保留。接口为 `POST /api/email/schedules/:id/share`，请求 `{ "targetId": 另一日程ID }`。共享关系不允许形成链或循环；后续时间发生分歧时不继续抑制独立提醒，需核对。

日程页用红色提示不同活动的时间重叠。共享的同一活动不视为冲突。时间窗重叠属于潜在冲突，能否自行错开需结合考试规则判断。

数据库 v10 将通知来源唯一性由单邮件改为「场次 + 邮件」，支持同一通知关联多个阶段；保留旧来源行和外键。升级前应做 SQLite 在线备份。

## 验证

运行 `pnpm check`，覆盖短信过滤、令牌鉴权、去重、多阶段拆分、正式时间补齐、补充通知匹配及完成状态保护。浏览器流程另验证短信入口、红色冲突、日期范围、暗色与手机布局。不访问通知中的外部网址。

## 界面与快速筛选

浅色与暗色模式统一使用分层卡片、清晰边框和高亮活动时间。日程概览可点击筛选全部、冲突及待正式通知的活动；冲突数字统计受影响日程数，并非冲突对数。搜索覆盖公司、岗位、考点、地址和考场。手机窄屏自动换行，冲突同时用红色边框和文字说明，避免只靠颜色判断。

## Windows 接收服务常驻

`scripts/desktop/FindJob-ensure.mjs` 可作为 Windows 计划任务入口，使用本机 Node 执行，不需要改变 PowerShell 脚本签名策略。设置当前用户登录时触发，并每分钟重复检查；多实例策略设为 IgnoreNew，执行时间不限，允许使用电池时运行。任务仅在用户登录期间运行，不保存用户密码。

启动器从 `server/data/sms-gateway.env` 加载短信配置，主端口已占用时不重复启动或终止其他进程。它等待所启动的服务退出，下一次触发重新启动；日志保存在 `server/data/managed-server.log` 和 `managed-server-error.log`。这用于恢复进程退出，不会自动终止仍在运行但无响应的进程。

主动停止前创建 `server/data/service-paused` 文件，重新启动前删除该文件，避免自动恢复与主动停止冲突。电脑关机、休眠、退出登录或 Tailscale 断开期间无法接收，手机应配置失败重试。Tailscale Serve 仅代理短信端口，主应用端口继续限制本机访问。

## 新短信与历史短信

SmsForwarder 3.5.0 的“短信转发规则 → 全部转发”用于新收到的短信；“重发消息”用于已有转发日志，不等于导入手机安装前的全部历史短信。历史招聘通知可复制到 FindJob 的短信接入表单，并填写原始收到时间。目前没有历史短信文件批量导入入口。

规则级自定义模板可使用 `[org_content]` 保留原始正文；Webhook 通道内同名“消息模板”实际是 webParams，必须留空以发送默认表单。Headers 的 Key 为 `Authorization`，Value 为 `Bearer ` 加完整令牌。
