# 邮件自动化、时间线与主题升级

本说明对应 2026-10-12 的升级。旧文档中“所有事件按收件时间”“仅手动发送 300 字给模型”“AI 不推进状态”的描述由本说明替代。

## 时间口径

| 邮件类型 | 时间线依据 | 缺少信息时 |
| --- | --- | --- |
| 投递确认 | IMAP INTERNALDATE 收件时间，不使用发件人 Date 或分析时间 | 服务商缺少 INTERNALDATE 时标记待复核 |
| 笔试／面试／测评 | 正文或受支持附件里的活动时间，保留历史日期及时间段 | 不用收件时间冒充；留待人工填入时间 |
| Offer | 正文／附件明确的录用通知日期，否则用收件时间 | 不把入职日、报到日或回复截止日当录用日期 |
| 拒信／其他 | 收件时间 | other 不自动推进申请状态 |

日期在服务端按服务器本地时区归一化（国内使用建议 `TZ=Asia/Shanghai`），带 Z/偏移量的收件时间在浏览器按本地时区显示。跨时区部署应使服务器与使用者时区一致。

模型提取的活动时间需要同时提供能在脱敏正文或附件中找到的原文证据。界面分别显示收件时间、事件时间、来源、原文、置信度、附件解析结果与待复核原因。证据匹配不等于事实保证，歧义、改期、多轮邀请仍需人工检查。

没有投递回执、直接收到笔试或面试邮件时，可以关联已有申请或补建申请并进入相应阶段。**投递日期保持未知**，不会填成面试邀请日。状态机补齐的中间阶段会注明“实际发生时间未知”。后续补入较早投递回执只补投递日期和历史时间线，不回退当前状态。用户已填的投递日期不覆盖。

公司采用准确名称匹配，岗位采用准确名称；没有岗位信息时，只关联该公司的唯一申请。多条候选时拒绝猜测，邮件保持待处理。唯一的邮件导入占位岗位可在后续邮件提供明确岗位后补全。公司别名或岗位简称需要在确认界面改为已有名称。

## 增量分析与重复保护

默认每天服务器本地时间 08:00、20:00 运行，服务需保持启动。重启会补跑最近一个错过的时间槽，不累计补跑所有历史时段。

1. 首次按所选天数搜索，每个文件夹从较早 UID 开始，分批处理。
2. 游标绑定邮箱账号、服务器、文件夹、UIDVALIDITY，持久化在本地 SQLite `settings` 的 `email.uid.*` 中。
3. 后续定时／手动增量查询 `UID > 游标`，不是每天下载最近 N 天正文。只有本地成功记录分析结果、识别为无关或安全跳过后才推进游标。
4. 单批上限外的邮件留到下一轮；尚未持久化的消息在中断后可以重试。服务商更换 UIDVALIDITY 后重新扫描，Message-ID 去重继续生效。
5. 已存邮件不重复调用模型；无关邮件仅保存 Message-ID 与分析时间。跨文件夹重复邮件只分析一次，各文件夹分别推进游标。
6. “补扫并重分析待处理”忽略增量游标，补扫所选天数中最近 `IMAP_MAX_SCAN_MESSAGES` 封（默认每文件夹 30，最大 200），并可更新待处理结果。已应用和已忽略结果不被重写，历史补扫不改变增量游标。此操作会产生新的模型调用费用。

邮箱标记与本地游标独立：读取使用只读邮箱锁和 PEEK，不设置已读、不删除或移动邮件。线程内互斥防止手动分析与定时任务重叠；部署时只运行一个服务进程。IMAP FETCH 迭代器先完全排空，再请求正文，避免嵌套命令死锁。

## 附件与危险操作

支持 MIME/Base64/quoted-printable 正文解码、HTML 转纯文本；附件支持 PDF 文本、DOCX、XLS/XLSX、TXT、CSV、ICS、HTML。PDF／Word／Excel 在可终止的独立 worker 中解析，不启动 Office，不运行宏、脚本或公式，不读取附件中的外部资源。

| 限制 | 行为 |
| --- | --- |
| 单封 MIME 8 MiB；单附件 2 MiB；最多 5 个附件 | 超限标记待复核 |
| 正文 16,000 字；附件单个 16,000 字、合计 24,000 字 | 截断或超限明确提示，不自动应用 |
| worker 8 秒、JS 堆 128 MiB；PDF 最多 20 页 | 超时、加密、异常或页数超限留待人工查看 |
| Excel 最多 5 张表、每表 200 行 | 达到限制保守标记待复核 |
| 扫描 PDF、图片、旧 DOC、压缩包及程序附件 | 不做 OCR、不解压执行，明确提示人工查看 |

worker 堆限制不是操作系统级沙箱；解析库仍需及时更新。图片、扫描件、复杂多事件和歧义时间是当前明确的人工复核边界。

所有邮件 URL 在文本进入模型前被替换；HTML 的远程图片、脚本等被剔除。身份验证主题在本地跳过；常见验证码及邮箱地址脱敏。包含身份验证或一次性操作提示的招聘邮件会被标记待复核。系统不访问面试确认、一次性考试、取消订阅或任何正文／附件链接，不处理验证码，不发邮件、不接受 Offer、不提交考试／投递。需要用户在原邮箱完成的操作始终由用户完成。脱敏是尽力过滤，并非针对所有秘密格式的完美识别。

LLM 仅接收不可信数据做结构化提取，无工具调用权限。高置信度只是自动应用的条件之一：还需公司和明确事件、有效时间、无待复核原因；批量按收件先后处理，申请匹配失败保持待处理。申请创建、时间线、提醒与确认写入在事务中完成。已处理邮件不能重复应用。提醒只为未来开始／结束时间创建。

## 操作与配置

邮件分析页可查看自动计划、上次结果、下次时间和运行状态；“立即运行自动流程”执行分析及符合条件的自动应用，“增量分析新邮件”仅分析。两者执行时都会记录完成情况。分页可访问全部本地邮件。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `EMAIL_AUTO_ANALYZE` | `1` | `0` 关闭定时分析 |
| `EMAIL_AUTO_ANALYZE_HOURS` | `8,20` | 本地每日执行小时 |
| `EMAIL_AUTO_ANALYZE_DAYS` | `7` | 首次扫描回看天数，1–30 |
| `EMAIL_AUTO_APPLY` | `1` | `0` 仅分析、不自动生成追踪记录 |
| `EMAIL_AUTO_APPLY_MIN_CONFIDENCE` | `0.8` | 自动应用最低置信度 |
| `EMAIL_ANALYZE_MODE` | `llm-first` | `keyword` 使用本地关键词及规则 |
| `EMAIL_LLM_MAX_EMAILS` | `40` | 单轮分析数量上限 |
| `IMAP_MAX_SCAN_MESSAGES` | `30` | 每文件夹扫描上限，1–200 |
| `IMAP_MAX_SNIPPET_DOWNLOADS` | `15` | 每文件夹正文下载数量上限，增量批次同时受此限制 |
| `EMAIL_FETCH_BUDGET_MS` | `60000` | 每文件夹下载预算 |
| `IMAP_SOCKET_TIMEOUT_MS` | `30000` | 连接／问候／socket 超时 |

因下载失败或资源限制无法完整读取的邮件会进入待复核，避免仅靠主题自动落库到申请。可用历史补扫重试。失败的自动任务记下原因，到下一时间槽或手动运行再试，不每分钟重试。

新增 API：`GET /api/email/auto-analyze` 返回计划及 `running`；`POST /api/email/auto-analyze/run` 立即运行自动流程。`POST /api/email/analyze` 支持 `days`、`includeJunk`、`fullRescan`、`reanalyzePending`。提取结果增加 `timeSource`、`timeEvidence`、`reviewReasons`、`attachments`；手动修改的时间来源为 `manual`。

## 暗色界面

右上角选择浅色、暗色或跟随系统。选择保存在本浏览器，跟随系统会实时响应系统变化。主题覆盖导航、表格、表单、确认弹窗、消息提示、图表及 Markdown 预览。移动端控件换行，避免邮件操作区挤出屏幕。

## 验证与升级

```bash
pnpm install
pnpm check             # 单测、类型检查、构建、隔离 API 集成、合成附件测试
pnpm test:ui           # Edge 无头浏览器：主题切换、记忆、弹窗、图表、移动端
pnpm test:email:live   # 显式访问本地配置的邮箱及模型，需要网络，会产生模型费用
pnpm start
```

实时测试先用 SQLite backup 创建 `server/data/before-email-upgrade-*.db`，最多读取 5 封邮件、向模型提交其中最多 2 封招聘候选，不写邮件追踪或申请。审计与正常 OAuth token 刷新仍可写本地配置。输出只有数量、类别与结果，不输出邮件正文／地址／凭据。

本次真实测试：LLM 连通和合成面试时间提取通过；邮箱 5 封正文均解码成功；真实样本分别识别出无关邮件、投递确认（收件时间来源）。真实抽样中没有附件，附件能力另用合成 PDF、DOCX、XLSX 的 worker 端到端测试验证。主题浏览器检查通过；测试产物在被 Git 忽略的 `server/data/ui-review/`。

数据库 v7 仅新增无关邮件去重表；不会重写已有申请或已确认时间线。升级前备份数据库，升级后重启后端并刷新网页。旧的待处理结果可补扫重分析；旧版已确认的错误时间需在原记录中人工核对修正。

实现参考：[ImapFlow 客户端接口](https://imapflow.com/docs/api/imapflow-client/)、[MailParser](https://nodemailer.com/extras/mailparser)。

## 同公司多申请与考试准备事项（2026-10 修正）

- 新增 `recruitmentId`（职位编号）。有编号时只按同公司相同编号关联；不同编号即使职位名相同也不会合并。新建标题保留 `[编号]`，已确认邮件也保存编号依据。
- 缺少编号时只匹配唯一的完整岗位名称。岗位也缺失且公司已有申请时，停止自动应用，保留待复核；不再用“只有一条申请”猜测，也不再用新邮件改名覆盖未知岗位。
- 确认弹窗可搜索并指定已有申请，或选择新建独立申请。API `targetApplicationId` 为正整数时指定申请，`null` 时新建（需同时 `createIfMissing=true`），省略时按证据匹配；指定申请必须属于所填公司。
- 投递回执里描述未来可能被拒的通用文案不算拒信。职位编号不等于简历编号、考生编号或验证码。包含多个志愿的统一笔试通知不能证明每个志愿都推进到了同一阶段。

线下笔试、预约成功邮件按实际考试时间提取。雇主从主题和正文识别，避免把代发平台当成申请公司。预约窗口、准考证打印事项、客服营业时间不能充当考试起止；没有明确结束时间就留空。多地区场次必须确认本人考区，不能默认选第一场。HTML 排版的空白变化不再导致真实时间证据失配，但仍要求原文内容一致。

`preparationTasks` 保存 `{title, scheduledAt, timeEvidence}`，经原文验证后，应用邮件时写入独立的准备事项时间线与未来提醒。无明确打印时间时不会虚构打印截止。明确的英文 `End Login Date/Time` 是测评登录截止，不是考试开始；支持带 BST/GMT/UTC 的该模板日期并换算本机时区。普通本地规则仍低置信度，只有同时匹配明确雇主、岗位、职位编号和登录截止的受限测评模板可达自动应用阈值。

全局页面显示今天及未来 7 天的待办提示，自动分析结果列出待复核数量与关联失败原因。提醒是应用内待办，不是关机时仍会发送的系统推送。多考区待复核邮件需确认并应用，才能生成对应提醒。

附件解析改为隐藏的独立 Node 子进程：8 秒超时、128 MiB V8 堆上限，仍沿用文件数量和字节限制。仅继承必要操作系统环境变量，不继承邮箱／API 凭据。只有子进程正常退出且返回结果才接受文本，PDF 原生模块崩溃不会终止邮箱主服务；此隔离不是操作系统权限沙箱，也不包含图片 OCR。

已有错误关联不会随升级批量改写。修复时先 SQLite 在线备份，再核对职位编号、原文、目标申请及时间线；仅在事务中迁移确认归属的记录，保留人工记录，完成后校验外键和数据库完整性。真实邮件、数据库备份、定向修复脚本均留在忽略目录，不提交到 GitHub。正常增量分析与去重规则不变。
