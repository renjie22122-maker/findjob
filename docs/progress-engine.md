# 通用进度中枢与 MCP

进度中枢位于电脑网页版「助手」页面。它把来源、跟踪对象、活动和进展分开管理，而不是把所有通知塞进单个岗位状态。

## 使用方式

- 默认后台检查新增或内容变化的本地通知，不重复拉取邮箱。每轮最多 12 条新变化，补充同单位的旧通知作上下文，使用设置中已有的 AI API。
- 点击「自动整理近期通知」立即核查；或直接说「这个考完了」「把这场时间改到……」「这些岗位共用一次考试」。AI 给出结构化操作，服务端验证后执行并留记录。
- 不需要逐项批准普通关联和补齐待办。只有低置信度、缺失原文、过期版本或实际矛盾的操作会保留为异常，不会弹出逐条确认对话框。可继续发一句关键说明，也可展开处理记录检查保存方案。
- 图谱支持搜索、分页、点击节点、查看脱敏原文和带上下文对话。列表视图提供同一套关系，便于小屏和辅助技术使用。

## 通用模型

| 概念 | 存储/标识 | 作用 |
| --- | --- | --- |
| 公司、组织 | `company:N` | 提供岗位或项目的主体 |
| 申请 | `application:N` | 每个岗位/分行独立跟踪，不因共用考试而合并 |
| 活动 | `schedule:N` | 固定时间、截止时间、自由作答窗口；沿用原日程和提醒实现 |
| 来源 | `notice:N` | 邮件和短信；原文不作为可执行指令 |
| 通用事项 | `work:stable-key` | 自定义项目、任务、里程碑；kind、state、data 可扩展 |
| 关系 | `work_edges` | 多对多、有方向、有来源依据，如 participates、depends_on、passed |

已有实体在图中实时投影，不复制一套申请和日程数据库。自定义事项和关系使用独立表保存。普通关系只表示语义联系，不隐式改动申请状态或删除实体。一个活动可通过关系关联多个申请；已有重复场次还可共用一组提醒。后续分行面试继续分别跟踪。

自定义事项目前用于进度记录；需要系统日程提醒的招聘任务通过 `apply-notice` 落到原有提醒系统。不要把任意 `data.deadline` 当成已经创建了闹钟。该版本的引擎运行在电脑服务，尚未移植到 Android 的独立 SQLite/WorkManager 引擎。

## AI 与执行器分工

AI 负责跨通知理解主体、轮次、先后关系、通知意图和用户简短修改指令。`intent` 区分邀请、进展、待办、回执：考试通过不是新的考试；资料填报是带截止的待办；AI 面试和测评可在同一通知中分别建立活动。

执行器不硬编码公司业务规则，而是校验：

- 通知编号存在，连续引文确实在已保存的脱敏正文中。
- 时间、地点等仍通过现有证据校验；提到验证码不再阻断正文日期分析，但验证码与链接不参与执行。
- 申请、场次、事项使用稳定 ID；已有记录有版本，分析期间数据变化不覆盖旧方案。
- 重复请求 ID 返回已有结果，关系有唯一约束，申请/日程的写入复用原服务事务。
- 共用提醒保留两边的申请和已完成记录，保留独立准备事项；仅时间相同不自动认定同场。
- 自动运行没有用户授权文本，不能假装用户说过“已完成”。对话完成和改期必须引用当前用户消息，不能引用邮件中的指令。
- 每个操作单独事务执行；部分动作成功、部分未执行时，结果分别记录，不把模型建议当成执行结果。

状态、标题、关联关系可由 AI 扩展，但无法承诺覆盖所有未来场景。无依据的事实不会因为置信度高就变成真实事实。附件全文不在现有存量数据库时，该引擎不会静默猜测，也不会替用户打开远程附件链接。

## 后台与性能

服务调度器每分钟检查一次本地变化。`work_scan` 保存内容指纹，重启后继续；网络失败延迟 5 分钟再试，最多 3 次，避免持续调用 API。明确新内容会重新入队。单进程仅一项分析运行，其他请求返回 busy，不会把上一位请求的结果错误返回给下一位。

单次模型最多 40 条来源，每条正文最多 8000 字；默认手动入口选择最多 24 条待处理/近期通知。图谱分页 40/100 个匹配节点，并带最多 200 个直接邻居。界面声明范围，不声称一次遍历全部历史。来源正文只在点开时读取。

目前图谱投影和乐观锁指纹仍会扫描本地实体表；适合个人工作库，超大团队库应进一步改为按版本序列和数据库分页检索。MCP 与网页版共用同一数据库，不包含手机跨设备同步。

## MCP 接入另一个 agent

先在项目目录运行：

```powershell
pnpm --filter server build
```

在支持 `mcpServers` 配置的 agent 中加入以下服务。把路径改为实际安装路径；无需先启动网页服务器。使用 Node.js 20 或以上。

```json
{
  "mcpServers": {
    "careerflow": {
      "command": "node",
      "args": ["D:/Desktop/Project/findjob/server/dist/mcp.js"],
      "env": {
        "FINDJOB_DB_PATH": "D:/Desktop/Project/findjob/server/data/findjob.db",
        "CAREERFLOW_MCP_WRITE": "1"
      }
    }
  }
}
```

`CAREERFLOW_MCP_WRITE=1` 授予这个本机 agent 使用受校验写入操作的权限；不设置时只读。MCP 使用官方 SDK 的 stdio 协议，不开公网端口，不暴露配置、密钥、SQL 或 shell 工具。

| 工具 | 用途 |
| --- | --- |
| `progress_graph` | 查询/搜索关联图谱及当前 fingerprint |
| `progress_sources` | 按编号读取脱敏本地原文 |
| `progress_history` | 读取执行记录与异常 |
| `progress_analyze` | 调用本项目已配置 AI，自动分析并应用可验证操作 |
| `progress_apply_plan` | 外部 agent 自行分析后提交结构化方案；需新 fingerprint、稳定 UUID requestId |

工具 schema 自动暴露操作类型及参数。推荐让 agent 先取 graph → sources → analyze，或由它自行判读后 apply_plan。所有写入使用与界面相同的校验、事务和审计。不要发送数据库文件、API Key 或邮箱令牌给另一个 agent。

对另一个 agent 可以直接说：

> 使用 careerflow MCP 核查近期通知和进度；自动补充来源充分的关联与提醒，保留完成状态。用实际执行记录汇报结果，不要把关联等同于合并岗位。不访问通知链接，不进行登录或身份验证。

## 验证

```powershell
pnpm --filter server test
pnpm --filter server typecheck
pnpm --filter client build
node server/scripts/work-mcp-smoke.mjs
node server/scripts/work-ui-smoke.mjs
node server/scripts/work-live-smoke.mjs --live
```

最后一项显式使用配置的 AI API，但仅发送合成通知，在内存数据库验证实际写入，不修改真实申请。MCP 测试通过官方 SDK 客户端验证握手、工具发现、只读限制与输入校验。

## 多语言主体与关联搜索

公司别名单独保存。仅括号、空格或字形不同的名称自动归一化；中英文同一主体可由 AI 引用双方通知原文判读（置信度至少 0.98），或通过对话说明后关联。原公司记录、岗位、日程、完成状态保留，申请仅改指向规范公司，操作写入修复记录。已确认别名用于后续邮件和导入，避免英文名再次建立重复主体。

公司同一不表示岗位或活动同一。AI 可结合跨邮件的时间、阶段、岗位和场次编号，显式选择已有日程及版本；不同阶段继续分开跟踪。母子公司只建立组织关系，不因集团简称自动合并。

关系搜索先立即返回本地名称、别名及有序缩写匹配，再异步调用已配置 AI 补充中英文简称、集团相关组织。语义搜索结果只扩展检索词，不作为身份合并依据。公开搜索只向 Bing RSS 发送检索词及“公司 简称 官网”，不发送通知正文，不访问搜索结果中的链接；`CAREERFLOW_PUBLIC_SEARCH=0` 可关闭。查询缓存 24 小时，最多两个并行扩展请求；敏感样式查询不会送入搜索或模型。

关系图采用分层重排减少交叉，从卡片边缘连线；已有“通知—活动—申请”路径时隐藏重复的直达线，列表仍显示完整关系。复杂多对多关系不能保证完全无交叉。

`CAREERFLOW_WORK_AUTO=0` 可暂停后台 AI 进度整理，正常部署默认开启。原文和私人数据库不应提交 GitHub。

## 活动时间与提醒时间

待办、日程、申请详情和首页下一项使用同一时间展示组件。固定场次以大字展示开始与结束的完整日期时间；自选作答窗口以大字展示完成截止，开放时间放在次要位置。未提供结束时间不猜测，未知截止不借用开放时间。取消或待通知的日程不再突出旧时段。提前一天等提醒的触发时间独立显示，不能当作考试时间。

新增只读 MCP 工具 `progress_agenda`：参数为 `from`、`to`（含当天的 YYYY-MM-DD）、`done`、`offset`、`limit`（最多 100）。按活动开始日或完成截止日筛选；独立提醒以提醒日筛选。返回 `primaryTime`、`timeMeaning`、`deadline`、`reminderAt`、`occupiesWholeInterval` 和 `activity` 中的起止时间、时区、地点、状态。自选窗口不会标为全时段占用。没有时间且使用日期过滤的记录不会命中，不带日期过滤可查看它们。同一活动的提前提醒和到时提醒保留独立 ID；agent 可按 activity.id 分组展示，不能把一次准备提醒完成理解为整场考试完成。

验证：`node server/scripts/time-ui-smoke.mjs`；MCP 握手测试覆盖新增工具及非法日期输入。上述展示升级适用于电脑网页版（含窄屏布局），Android 原生端需另行移植。

## 日程摘要与图表明细

日程列表默认只展示公司与事项、岗位、关键时间、地点和重要异常。准备事项、场次编号、版本、来源及变更记录移入「查看详情」抽屉；调整与共用提醒也从详情进入。自选窗口按完成截止排序，固定场次按开始时间排序。

总览环图的扇区与类别按钮、漏斗图的图形与阶段按钮均可打开申请明细抽屉，支持分页和跳转岗位。环图按当前状态筛选；漏斗按历史阶段成员筛选，后续被拒或推进的申请仍属于曾到达的阶段。统计数量与明细查询共用 `funnelMembership` 定义，重复时间线事件不重复计数。

接口：`GET /api/stats/applications?status=WRITTEN_TEST&page=1&pageSize=20` 或 `?stage=interviewed`，status 与 stage 二选一；stage 可选 applied/interviewed/offer，每页最多 100 条。不改变其他页面已有的申请筛选条件。

待办卡片以公司为主标题、岗位为次标题，准备/考试等具体事项另起一行；避免提醒文案遮盖公司身份。图表弹出明细或窗口缩放时清理浮层，避免旧提示框造成小屏横向溢出。

## 预约日程、岗位变化与自动归档（2026-11-05）

- 明确“具体时间以预约为准／另行通知”的邀请以 `awaiting_time` 跟踪，保存可核对的日期范围、地点和独立预约截止事项，不虚构午夜面试场次。后续正式场次在同申请、活动类型及日期范围内唯一匹配后补全；冲突场次保留核对。
- 准备事项使用自身截止时间展示，即使所属面试仍待预约也能正常提醒。重复通知与补全操作保留已完成提醒。
- AI 跨邮件识别的中英文重复通知通过 `apply-notice` 归档并追加同一活动来源；仅创建图谱边不代表通知已处理。自由作答预通知有明确窗口即可提醒，不必等待链接邮件。
- 唯一待定申请遇到正文明确岗位可补全岗位名称。明确已发生的岗位调剂由模型提供 `applicationChange: {kind:'transfer',fromPositionTitle,evidence}`，验证同一单位、唯一原岗位及包含新旧岗位的原文后更新申请并记录前后名称。调剂意愿询问不自动修改岗位；独立岗位不据公司名称合并。
- 后台优先处理待处理通知，部分操作失败进入有限退避重试；新解析策略会重新检查旧的待处理通知。用户已完成状态不会因重分析被清除。

验证：279 项服务端回归通过；前后端构建通过；已用本地两封真实通知和已配置 AI API 验证待预约日程、岗位补全及跨语言归档。未访问邮件链接或执行预约、身份验证。本轮为桌面服务端改进，Android 独立分析引擎尚未包含这些新语义。
